# USB4 TP2 on GUFO 0.30.0

This optional build ports the native two-rank implementation from
`neuhaus/gufo` RDMA revision `f070a179c628a7409a5cee8e07b1ca76f1f7e660`
to upstream 0.30.0 (`f801b8cac07428191d3fb8923926f31f13dde795`).
It is a source port; the official 0.30.0 runtime does not include TP2 flags.

Build with `GUFO_ENABLE_TP2_RDMA=ON`, or the `tp2-rdma` Nix package.
The default build retains upstream's component cache. Even in a TP-enabled
build, component providers use the standard pool; only a native runner uses
the mirrored pool. The paired native cache follows 0.30's prefill alignment
contract, preserves decoded live frontiers and exact full-prompt retries,
and isolates disk compatibility from older paired snapshots.

The model executor keeps upstream's multi-checkpoint path for one host and
uses rank-local tensor geometry and reductions for TP2. Rank 0's draft plans,
prompt images, constraints, snapshots, cancellation and disk operations are
mirrored to rank 1. TP2 still uses separate bounded prefill/capture calls,
as documented in [TP2.md](TP2.md).

The runtime links rdma-core 65. A USB4 userspace provider must match its
`rdmav65` ABI; the earlier `rdmav59` plugin cannot be reused. The local
provider package preserves the existing native driver's CQ-capacity fix.
No kernel module, host provider, model weight or cable configuration needs
replacement for this userspace port.

## Validation checkpoint

On the user's first Strix Halo server, with pinned ROCm 10.1/HIP Clang 24:

- The production build succeeds; the RDMA control and mirrored cache suites pass.
- The standard component cache, runner and scheduler suites pass.
- Six existing GPU suites pass: MTP, GDN, attention, projections, snapshot
  copies and wide verification/rollback. The wide test's synthetic model
  initializes the same full-head geometry as the production loader.
- The added native-cache regression rejects unaligned prompt prefixes while
  retaining exact retries, aligned fallbacks and decoded live frontiers.
- Pinned C++ formatting, generated infrastructure, dependency records and
  extension API checks pass. The new optional runner hooks have a permanent
  0.1 API change record.

Live dual-USB inference qualification and performance measurement are pending
at this source checkpoint. No performance improvement is claimed.
